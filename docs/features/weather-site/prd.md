## 1. 背景与问题陈述

### 1.1 业务背景
【确认】建设城市天气查询网站，支持桌面和移动访问。用户输入城市，查看温度、体感温度、天气状况、湿度、风速及未来预报；第三方密钥不得暴露在前端。

### 1.2 当前痛点
以下为报告提出的场景风险，尚无实测频率或影响人数。

1. 同名城市可能误选 → 结果属于错误目的地，影响所有涉及重名的查询。
2. 单位、更新时间、日期归属不清 → 跨时区出行时可能误读天气与预报日期。
3. 等待无反馈、空结果与失败混淆 → 用户无法判断修改城市还是重试。
4. 快速切换城市可能串位 → 较慢旧请求覆盖新结果。

### 1.3 如果不做
用户仍需借助其他天气渠道完成查询；这是场景推导，尚未验证其替代工具。若只展示数值而不解决地点、日期及异常歧义，网站无法可靠完成本次查询任务。

### 1.4 为什么现在做
2026-10-16 需求完善报告已获确认，当前任务明确要求进入 PRD 与质检阶段。先确定可验收规则，避免设计与研发分别解释重名城市、五日范围和密钥保护；无外部市场时机证据。

查询可用率中 ready 与 partial 均计分子，error 不计；分母含已终结的 ready/partial/error，排除取消、旧版本失效、测试、未选择城市及仍在途查询。完整成功率只计 ready；另报数据 completeness=complete 的严格完整率。自动刷新、手动刷新、重试按独立 attempt_id 分组，不重复计首次查询。

**修订基准协议（B05）**：预发布环境使用与计划生产一致的构建、实例规格、网络区域及缓存配置，QA 记录具体参数。固定支持城市夹具不少于 20 个，50 个并发会话每次仅发一个选城天气查询；预热 1 分钟，正式采样 10 分钟且有效样本不少于 1000。端到端从浏览器触发选城/刷新请求，到当前与预报两模块均呈现终态（含渲染）计时，不含用户输入与选城思考时间。缓存命中和强制缓存未命中两组分别报告 P95 并均须≤3s；记录上游响应分布、错误率、硬件与浏览器版本，不用即时假数据代替真实供应商链路。故障注入用例单独报告。

仅以服务端明确记录 upstream_timeout 的样本排除 P95，并报告其数量、比例与完整未排除分布；5xx、网络错误重试及普通失败样本不因“慢”而剔除。仅返回快速错误不能认定性能达标，健康链路样本必须满足完整结果验收；不存在实测成绩，待 RD/QA 执行。

## 3. Non-Goals（不做什么）

1. 不做登录、账号与收藏 → 原始任务未要求，首期无需持久化个人记录。
2. 不做定位授权、地图、附近城市 → 首期入口为手动城市名称查询。
3. 不做逐小时天气、空气质量、降水概率、预警 → 报告未纳入基线，不扩展数据采购与展示范围。
4. 不做单位切换、多语言界面、离线天气 → 单位已确认；检索覆盖仍待确认，首期中文界面。
5. 不做管理后台、报表导出、邮件/短信/推送 → 查询结果在当前页面反馈，运行监控使用既有技术工具。
6. 不承诺任意输入语言或全球城市全覆盖 → 必须先验证供应商检索与预报能力。

#### US-01：搜索与重名选择（P0）

**前置条件：** 搜索服务已配置。

**验收标准：**

- [ ] AC01-01：trim 后为空不请求；按 Unicode 码点计数 1–100 可提交，101 拒绝；前后端一致，保留汉字、空格、连字符与重音，输入以文本展示。

#### US-02：读取当前天气（P0）

**作为**访问者，**我希望**查看五指标及数据时间，**以便**理解当前情况。

**前置条件：** 已选有效城市。

**验收标准：**

- [ ] AC02-01：完整数据展示温度、体感、状况、湿度、风速；固定 °C/m/s/%；换算后按 §7.2 舍入，0 不当作缺失。
- [ ] AC02-02：个别气象字段无效显示 --，保留其他有效字段；五项全无效为模块失败。更新时间、reference_at 或可信城市时区缺失/无效，即使五指标齐全也失败，不拿请求时间冒充观测时间。
- [ ] AC02-03：当前数据年龄 15 分钟整可用，超过 15 分钟不可作为有效当前天气；缺失时间、任何晚于可信服务端当前时刻的观测时间均失败（未来容差 0）；缓存命中或直接上游响应均适用。
- [ ] AC02-04：当前缓存 fetched_at+10 分钟前可命中，等于或超过 10 分钟失效；读取时还须通过 15 分钟观测年龄检查；缺失/非法时间不得写为有效缓存。

**排除：** 推断缺失气象数值、气象精度保证。

**前置条件：** 已选城市且有可信城市时区。

- [ ] AC03-02：整日三个气象字段全无效时，该日为失败占位；个别字段无效显示 -- 并保留其他字段。五个系统日期标签不计有效气象数据；五日全空则模块失败。
- [ ] AC03-03：同日完全相同记录去重；冲突重复记录逐字段合并：相同有效值保留、唯一有效值保留、不同有效值冲突则该字段 --。温度对 max<min 时两温度均 --，有效状况保留；最终按 §5.4 判定。

## 5. 业务流程与状态机

### 5.1 整体业务流程图

```text
idle → 合法搜索 → searching → candidates → 显式选城 → loading
                   ├→ empty                   ├→ ready（成功/成功）
                   ├→ no_selectable           ├→ partial（成功/失败）
                   └→ search_error            └→ error（失败/失败）
ready/partial/error → 手动刷新或当地午夜 → refreshing → 同一终态矩阵
模块失败/数据不全 → 区块重试 → loading/refreshing → 重新聚合
任意状态 → 切换城市 → 旧版本失效，清空旧城天气 → loading
```

### 5.2 状态定义

| 状态标识 | 显示名称 | 描述 | 可执行的操作 | 操作角色 |
|---|---|---|---|---|

## 7. 详细功能设计

下述为统一实现契约，参数来源按首页决策表区分。页面顺序：搜索 → 候选/搜索状态 → 所选城市与时间 → 当前天气 → 五日预报 → 来源；每个节点均含字段、联动、按钮、通知与异常。只读字段“必填”指数据契约，不能让用户补气象数据。

### 7.1 搜索与候选

#### 页面结构
带标签输入框、搜索按钮、状态文本、候选列表；初始提示“输入城市名称查询天气”。不做输入自动补全。

#### 表单字段

| 字段标识 | 显示名称 | 类型 | 必填 | 默认值 | 取值范围 / 枚举值 | 校验规则 | 数据来源 | 备注 |
|---|---|---|---|---|---|---|---|---|
| query | 城市名称 | 文本 | 是 | 空 | trim 后 1–100 Unicode 码点 | 不按 UTF-16 单元/字节计；不执行 HTML | 用户 | 修订细则 |
| city_key | 地点键 | 字符串 | 是 | 无 | 服务端检索映射中有效键 | 类型/格式/长度按冻结契约，拒绝任意 URL | 检索服务 | 绑定 ID 或合法经纬度 |
| name | 城市 | 文本 | 是 | 无 | 非空 | 缺失禁选 | 上游检索 | 文本转义 |
| country | 国家/地区 | 文本 | 是 | 无 | 名称或可信代码映射 | 缺失一律禁选，不因经纬度可区分而豁免 | 上游检索 | B03 歧义关闭 |
| admin | 行政区 | 文本 | 否 | 暂无行政区信息 | 供应商层级 | 不编造 | 上游检索 | 显示可用值 |
| coordinates | 经纬度 | 数值对 | 消歧时是 | 无 | lat[-90,90],lon[-180,180] | 有限值；不能替代必填 name/country/key | 上游检索 | 必要时展示 |

#### 字段联动规则

| 触发条件 | 联动效果 |
|---|---|
| 输入变化 | 候选和旧搜索失效，旧城市结果继续带原城市标签 |
| 候选存在 | 统一手动选择，单项也不自动跳过 |
| 必填齐全但名称仍相同 | 补经纬度；仍不可区分则禁选并提示缩小查询 |
| 选择同城市/新城市 | 同城市触发刷新；新城市清空旧快照后取两模块 |

#### 列表与筛选

| 列名 | 字段来源 | 是否可排序 | 默认排序 |
|---|---|---|---|
| 城市/国家/行政区/必要经纬度 | 候选字段 | 否 | 保留供应商相关度顺序 |

| 筛选项 | 类型 | 选项/格式 | 默认值 |
|---|---|---|---|
| 城市名称 | 文本 | query | 空 |

无分页；city_key 去重，最多 20 项。截断时提示“候选较多，请补充城市名称”；供应商返回上限由 OQ-01 验证，不能伪造候选。

#### 操作按钮

| 按钮名称 | 触发动作 | 可见条件 | 可点击条件 |
|---|---|---|---|
| 搜索 | 本地校验后请求 | 始终 | 非同 query 在途；非法输入仅校验 |
| 选择城市 | 固定 city_key 并取数 | 候选存在 | 必填及消歧通过 |
| 重试搜索 | 重发失败 query | search.error | 输入未变、非在途、冷却结束 |

#### 通知消息

| 触发事件 | 通知对象 | 通知方式 | 通知内容模板 |
|---|---|---|---|
| 初始/搜索中 | 当前访问者 | 页内状态区 | 输入城市名称查询天气 / 正在搜索城市 |
| 候选可选 | 当前访问者 | 状态区及焦点 | 找到 {count} 个候选，请选择城市 |
| 全禁选 | 当前访问者 | 状态区 | 暂无可选择城市，请补充城市名称 |

#### 异常与边界处理

| 场景 | 触发条件 | 系统行为 | 用户提示文案 |
|---|---|---|---|
| 输入空白/超长 | trim 后 0/101 码点 | 前后端拒绝，不取天气；前端不请求 | 请输入城市名称 / 最多 100 个字符 |
| 零候选 | 合法响应 count=0 | empty | 未找到匹配城市，请修改名称 |
| 全候选禁选 | count>0 但可选0 | no_selectable，不当网络失败 | 暂无可选择城市，请补充城市名称 |

| 搜索失败/超时 | 网络/上游/10s预算用尽 | error，保留输入 | 城市搜索失败，请重试 |
| 旧搜索返回 | 版本失效 | 静默丢弃 | 无 |

字符夹具：emoji 😀 计 1 码点；组合序列 e+U+0301 计 2，预组合 é 计 1；不在校验前静默 Unicode 归一化，trim 规则前后端使用相同 Unicode 空白集并以共享夹具核对。

#### 表单字段

| 字段标识 | 显示名称 | 类型 | 必填 | 默认值 | 取值范围 / 枚举值 | 校验规则 | 数据来源 | 备注 |
|---|---|---|---|---|---|---|---|---|

**跨午夜机制**：用可信 reference_at 与城市时区计算下一当地午夜；前台在午夜发起一次两模块自动刷新并共享新 reference_at（10s预算确保5分钟内有终态），新五日范围前移。休眠/后台标签由可见性恢复、pageshow、设备唤醒时检查“当地日期是否已变”，若变则立即刷新；若浏览器冻结执行、断网或设备休眠，不能保证物理5分钟内联网成功，恢复后立即尝试并明确提示“页面暂停期间未及时更新”。验收分为持续前台5分钟硬门槛和后台恢复立即触发，不把执行限制隐藏为成功。

失败后每个城市每个新当地日最多自动触发一轮，避免失败循环；提供可见手动刷新/重试。切城重新安排午夜任务并取消旧城市任务。两模块整体刷新共享基准；独立区块重试各自生成基准，预报显示自己的范围基准；发现已跨日即升级为两模块整体刷新，避免只更新一个模块日期。当前数据展示期间到15分钟边界后失效，即使页面未到午夜也须标已过期并可手动刷新。

**缓存与快照区分**：缓存是服务端有TTL的复用数据；快照是当前页面历史显示。缓存过期不延长TTL，不把上游失败时过期缓存当新结果；同城刷新失败保留旧快照，即使超过15min也只能放“历史数据，已过期”区域。预报历史快照展示原日期和 fetched_at。首次失败无快照则只展示失败占位。缓存键包含规范地点键、数据类型、单位与供应商，预报还需日期基准校验；不跨城市复用。

**强制安全执行**：所有入口先验证参数并按可信IP计数，再读缓存；仅在允许出站时扣第三方账号预算（首次和重试都扣），原子限流覆盖多实例。反向代理只接受可信代理注入的真实IP；用户自带转发头不可信。白名单只由服务端配置，限制HTTPS主机/路径，默认禁重定向；解析后地址必须为允许的公网服务，禁止私网/环回/保留/链路本地/元数据等目标及DNS重绑定。客户端不得指定URL/host/端口。供应商401/403/429不自动重试；预算耗尽且无有效缓存时拒绝出站。生产L/W、预算窗口及白名单必须有负责人批准记录才能发布。
